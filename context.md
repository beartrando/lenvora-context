# Lifecycle AI-агента для GitHub Issues

## 1. Создание задачи

Product Owner:

1. Создаёт GitHub Issue.
2. Заполняет описание задачи.
3. Помещает задачу в соответствующую колонку GitHub Project.

Это единственная точка, с которой начинается жизненный цикл задачи вручную.

---

## 2. Выбор задачи daemon'ом

Daemon на рабочей машине периодически проверяет GitHub Project.

Если находится задача, готовая к автоматической обработке:

1. daemon выбирает задачу;
2. передаёт её OpenCode / AI-агенту;
3. запускается новая итерация жизненного цикла.

---

## 3. Начало итерации AI-агента

Каждая итерация **обязательно начинается с восстановления контекста**.

Агент читает:

1. описание GitHub Issue;
2. все комментарии Issue;
3. все связанные Pull Request;
4. все комментарии связанных Pull Request;
5. текущий task-specific Wiki context;
6. общий архитектурный контекст проекта из отдельного context repository.

Только после восстановления полного контекста агент начинает анализ и работу.

---

## 4. Обновление task context

В начале работы агент обновляет task-specific Wiki context.

В Wiki фиксируется актуальное состояние задачи, например:

- что требуется сделать;
- что уже сделано;
- текущее понимание задачи;
- принятые решения;
- обнаруженные ограничения;
- состояние реализации;
- открытые вопросы;
- связанные PR / ветки.

Wiki используется как сохраняемое состояние задачи между итерациями.

---

## 5. Работа над задачей

AI-агент выполняет необходимую работу:

- анализирует код;
- изменяет код;
- запускает тесты;
- анализирует результаты;
- при необходимости повторяет изменения и проверки.

Если для продолжения работы информации недостаточно, агент переходит в состояние `Clarification`.

---

## 6. Требуется уточнение

Если агенту требуется информация от человека:

1. агент формулирует вопросы;
2. добавляет вопросы непосредственно в GitHub Issue;
3. обновляет task-specific Wiki context;
4. перемещает задачу в `Clarification`;
5. завершает текущую итерацию.

После этого агент больше ничего не делает до появления ответа человека.

Оператор получает уведомление о необходимости внимания, например через Telegram.

---

## 7. Ответ человека

Человек отвечает на вопросы в GitHub Issue.

После изменения задачи daemon обнаруживает событие и запускает следующую итерацию.

Новая итерация снова начинается с полного восстановления контекста:

- Issue;
- комментарии;
- PR;
- комментарии PR;
- Wiki context;
- общий архитектурный context repository.

---

## 8. Завершение работы

Если агент считает, что задача полностью выполнена и дополнительных вопросов нет:

1. обновляет task-specific Wiki context;
2. создаёт feature branch;
3. выполняет финальную проверку;
4. создаёт Pull Request из feature branch в `dev`;
5. добавляет ссылки на все связанные PR в GitHub Issue;
6. перемещает задачу в `Review`;
7. завершает текущую итерацию.

---

## 9. Review

Задача находится в `Review`.

На этом этапе требуется внимание оператора:

1. оператор проверяет изменения;
2. проверяет Pull Request;
3. при необходимости оставляет комментарии / замечания;
4. после этого задача может перейти в следующую итерацию жизненного цикла.

---

# Состояния GitHub Project

| Состояние | Назначение |
|---|---|
| `Backlog` | Все созданные задачи |
| `Todo` | Задачи, готовые к обработке |
| `In Progress` | AI-агент выполняет работу |
| `Clarification` | AI ожидает ответа человека |
| `Review` | Работа завершена, требуется ревью |

---
