# Responsibility

Логика модуля — сценариями в духе gherkin, но на русском:
`Функция` → `Сценарий` → `Дано` / `Допустимо` / `Когда` / `Тогда` / `И`.

## Функция: `AiService` — единая точка доступа к AI-клиенту

### Сценарий: создание сервиса по конфигу

- Допустимо передан конфиг `{ apiKey, baseUrl, model }`.
- Когда вызывается `new AiService(config)`.
- Тогда фабрика `createAiClient` вызывается ровно один раз с этим конфигом.
- И сервис хранит клиента, реализующего интерфейс `AiClient`.
- И ни одного сетевого запроса при конструировании не происходит.

### Сценарий: запрос к модели

- Дано сервис создан, а клиент в ответ на `chat` возвращает `"ответ модели"`.
- Когда вызывается `service.process("привет")`.
- Тогда клиенту передаётся ровно одно сообщение `{ role: "user", content: "привет" }`.
- И возвращается строка `"ответ модели"` без обработки и преобразований.

### Сценарий: системная роль не подмешивается

- Дано `process` вызван с любым текстом.
- Когда смотреть на переданные сообщения.
- Тогда ролей `system` и `assistant` в них нет — `process` всегда кладёт текст в `user`.
- И формирование промптов этому модулю не принадлежит.

## Функция: `createAiClient` — фабрика клиента

### Сценарий: выбор реализации

- Дано любой валидный `AiConfig`.
- Когда вызывается `createAiClient(config)`.
- Тогда возвращается экземпляр `OpenRouterClient`.
- И до появления другого провайдера ветвления нет: фабрика — единственная
  точка, где это решение принимается.

## Функция: `OpenRouterClient` — адаптер OpenRouter/OpenAI-совместимого API

### Сценарий: чат-комплит

- Дано конфиг `{ apiKey, baseUrl, model }`; клиент SDK создан с `apiKey` и `baseURL`.
- Когда вызывается `chat(messages)`.
- Тогда SDK `openai` выполняет `chat.completions.create({ model, messages })`.
- И возвращается `choices[0].message.content`.

### Сценарий: провайдер вернул ответ без текста

- Дано в `choices[0].message.content` нет значения (`undefined`/`null`).
- Когда вызывается `chat(messages)`.
- Тогда результат — пустая строка `""`, а не исключение.
- И ошибка самого запроса (сеть, 4xx/5xx) пробрасывается наружу как есть:
  обработка, ретраи и маппинг ошибок этому модулю не поручены.

## Функция: конфигурация задаётся снаружи

### Сценарий: в модуле нет чтения окружения

- Дано в `src/infrastructure/ai/` нет обращений к `process.env`.
- Когда нужен доступ к провайдеру.
- Тогда вызывающая сторона сама собирает `AiConfig { apiKey, baseUrl, model }`
  и передаёт его в `new AiService(config)`.
- И дефолты, и чтение env — забота wiring в `composition/`, не этого модуля.
